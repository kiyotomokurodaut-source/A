# 赤門ひろば — 東大生向けの情報交換掲示板

東京大学の学生を主な利用者に想定した、掲示板と Twitter 風タイムラインを混ぜたアプリです。
**匿名でテキストと画像を投稿でき、R18 相当の画像は自動で止まります。**
フォロー・DM・いいね・リポストもあります。

このディレクトリは、リポジトリの他の部分（黒田塾の静的サイト）とは独立しています。
`public/` のビルドや配信には一切関係しません。

## できること

| 機能 | 実装 |
| --- | --- |
| 匿名投稿（テキスト＋画像最大4枚） | スレッド内・その日限りで安定する匿名 ID 付き |
| 登録なしの書き込み | ゲストアカウント（匿名投稿のみ。いいね・フォロー・DM は不可） |
| R18 画像の規制 | アップロード時に自動判定 → 公開／確認待ち／拒否の三択＋ハッシュ再投稿の遮断 |
| 板（カテゴリ） | 全般・授業・進学選択・研究室・サークル・生活・就活・売買 |
| フォロー | フォロー中タイムライン（実名投稿とリポストが流れる） |
| いいね・リポスト | 取り消し可。件数は投稿に表示 |
| 返信 | スレッド表示（親をたどる＋返信一覧） |
| DM | 1対1。未フォロー相手からのものは「リクエスト」として区別 |
| 東大メール確認 | `u-tokyo.ac.jp` 宛のコード確認で認証バッジ。認証が要る板を用意 |
| 通報・管理 | 通報フォームと管理者用キュー（画像の公開／ブロック、投稿削除） |
| 検索 | 本文の部分一致 |

## 動かす

```sh
pip install -r bbs/requirements.txt   # Pillow（画像の自動審査と EXIF 除去に使う）
python3 -m bbs.server --demo          # 動作確認用のデータを入れる（任意）
python3 -m bbs.server --port 8787     # http://127.0.0.1:8787/
```

`--demo` で入るアカウント（パスワードはすべて `demopass123`）:
`komaba_1` / `hongo_lab` / `shinfuri_memo` / `circle_kanji`、管理者は `moderator`。

既存ユーザを管理者にするには:

```sh
python3 -m bbs.server --make-admin <ユーザ名>
```

データは `bbs/data/`（SQLite の `board.db`、画像、署名鍵）に置かれます。
場所を変えるなら `BBS_DATA_DIR` を指定してください。

### テスト

```sh
python3 -m unittest discover -s bbs/tests -t .
```

サーバを実際に立てて HTTP で叩く結合テストです（31 件）。
匿名性、権限、レート制限、画像の審査、EXIF 除去までここで確認しています。

## R18 判定について（重要）

内蔵の判定器は**機械学習の分類器ではなく、肌色領域のヒューリスティック**です。

1. 中身のバイト列から形式を判定（拡張子や Content-Type は信用しない）。JPEG・PNG・WebP・GIF のみ。
2. Pillow で開き直して**再エンコード**。これで EXIF（GPS を含む）が落ち、
   画像に偽装した実行ファイルの類も通らなくなります。長辺は 2048px に縮小。
3. 160×160 に落としてから、RGB 則と YCbCr 則の両方を満たす画素を「肌」とみなし、
   - 肌の面積比
   - 最大の連結領域の比（= 大きな一続きの肌）
   - 隣接画素の細かな揺れ（写真らしさ。ベタ塗りやグラデーションはここで落ちる）
   からスコア 0〜1 を作ります。
4. `0.62` 以上は**拒否**（保存もしない。ハッシュを記録して再投稿も止める）、
   `0.38` 以上は**確認待ち**（保存はするが公開しない）、それ未満が公開。
   アニメーション（GIF・WebP）は全フレームを見られないので、常に確認待ち。

**取りこぼしと誤爆は必ずあります。** イラストや部分的な露出には弱く、
逆に肌色の面積が大きいだけの写真（接写、砂浜、木肌）を止めることがあります。
だから「疑わしい」を公開ではなく保留に倒し、通報と管理キューを併用する設計にしています。

精度が要るなら、外部の分類器に差し替えてください。

```sh
export BBS_NSFW_ENDPOINT=http://127.0.0.1:9000/classify
```

画像のバイト列を POST するので、`{"score": 0.0〜1.0}` を返すだけの HTTP サーバを用意すれば
そちらが使われます（NSFW.js、CLIP 系、商用 API のラッパなど）。
外部が落ちているときは内蔵判定に落ちます（＝保留側に倒れます）。

Pillow が入っていない環境では自動判定ができないので、**画像はすべて確認待ち**になります。
公開されるまで誰にも見えないので、安全側に倒れます。

## 匿名の扱い

- 匿名投稿では、表示名もユーザ名も他の利用者には出ません（API の応答にも含みません）。
- 代わりに `ID:xxxxxxxx` が付きます。これは `HMAC(サーバ鍵, 投稿者 ID + スレッド + 日付)` で、
  同じスレッドの同じ日だけ一致します。自演は見分けられますが、
  スレッドをまたいだ追跡や、外部からの逆算はできません。
- 自分のプロフィールでは自分の匿名投稿も見えます。他人のプロフィールには出ません。
- フォロー中タイムラインには匿名投稿を流しません（誰のものか推測できてしまうため）。
- **運営は DB で投稿者をたどれます。** 犯罪予告や重大な権利侵害に対応するための設計上の割り切りで、
  画面の注意書きにもそう書いてあります。

## 設定（環境変数）

| 変数 | 既定 | 説明 |
| --- | --- | --- |
| `BBS_HOST` / `BBS_PORT` | `127.0.0.1` / `8787` | 待ち受け |
| `BBS_DATA_DIR` | `bbs/data` | DB・画像・鍵の置き場所 |
| `BBS_SECRET_KEY` | 自動生成 | 匿名 ID とコードの署名鍵。**変えると既存の匿名 ID が変わります** |
| `BBS_DEV` | `1` | `1` のとき確認コードを API 応答に含める。本番では `0` |
| `BBS_NSFW_BLOCK` / `BBS_NSFW_REVIEW` | `0.62` / `0.38` | 判定のしきい値 |
| `BBS_NSFW_ENDPOINT` | なし | 外部判定器 |
| `BBS_MEDIA_MAX_BYTES` | 8MB | 1枚あたりの上限 |

## API

すべて JSON。状態を変える操作は `X-CSRF-Token` ヘッダ（`GET /api/me` が返す値）が要ります。

```
POST   /api/register | /api/login | /api/logout | /api/guest
GET    /api/me                     PATCH /api/me
POST   /api/verify/request | /api/verify/confirm
GET    /api/boards
GET    /api/timeline?kind=public|home|board|user[&board=|&handle=][&cursor=][&limit=]
POST   /api/posts                  GET/DELETE /api/posts/<id>
POST   /api/posts/<id>/like | /api/posts/<id>/repost
GET    /api/users/<handle>         GET /api/users/<handle>/follows?kind=following|followers
POST   /api/users/<handle>/follow
POST   /api/media                  GET /media/<id>
GET    /api/dm | /api/dm/<thread>  POST /api/dm
POST   /api/reports                GET /api/report-reasons
GET    /api/admin/queue            POST /api/admin/media/<id> | /api/admin/reports/<id>
```

画像は multipart ではなく、**バイト列をそのまま POST** します（`Content-Type: image/jpeg` など）。
応答の `media.id` を投稿の `media_ids` に入れてください。

## 構成

```
bbs/
  server.py      HTTP とルーティングだけ。エントリポイント
  models.py      SQL とデータ操作（匿名化・タイムライン・DM・通報）
  moderation.py  画像の審査（形式・EXIF 除去・R18 判定）
  auth.py        パスワード（scrypt）・セッション・CSRF・レート制限・匿名 ID
  db.py          SQLite 接続とスキーマ初期化
  config.py      設定（環境変数で上書き）
  schema.sql     テーブル定義
  seed.py        デモデータ
  static/        画面（素の HTML・CSS・JS。ビルド不要）
  tests/         結合テスト
```

## 本番に出す前に

このコードは**そのまま公開する前提の完成品ではありません**。少なくとも次が要ります。

1. **TLS とリバースプロキシ。** `http.server` を直接外に出さない（nginx / Caddy の背後に置く）。
   `BBS_DEV=0` にして確認コードの露出も止める。
2. **メールの実送信。** いまは確認コードを発行するだけで送っていません。
   `POST /api/verify/request` に送信処理を足してください。
3. **画像判定の差し替え。** 上記のとおり内蔵判定は簡易です。公開運用なら分類器を立てる。
4. **削除依頼の窓口と規約。** 権利侵害・名誉毀損の申し出をどこで受けるか、
   誰がどの基準で消すかを決めて明記する。大学名を掲げる以上、
   大学とは無関係である旨も書いたほうが安全です。
5. **バックアップ。** `bbs/data/` を丸ごと（SQLite は WAL も含めて）。
6. **保存期間の方針。** 通報やアクセスの記録をいつまで持つか。

## 既知の制限

- 通知（いいね・フォロー・返信）はありません。未読は DM だけ数えます。
- 引用リポスト、画像付き DM、ブロック／ミュート、ハッシュタグは未実装です。
- 全文検索は `LIKE` の部分一致なので、件数が増えると遅くなります（FTS5 に置き換える想定）。
- レート制限はプロセス内のメモリなので、複数プロセスで動かすと緩くなります。
- SQLite の単一ファイルなので、同時書き込みの多い規模には向きません。
